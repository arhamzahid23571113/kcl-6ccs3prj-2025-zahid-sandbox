\section{Awareness of Professional Issues}
\label{sec:professional_issues}

This project studies adversarial examples and black-box attack procedures.
That topic has clear professional significance because the same technical knowledge can be used either to improve robustness or to support harmful misuse.
The project therefore raises issues of dual use, responsible communication, data handling, research integrity, resource use, and dependence on third-party software.

\subsection{Dual use and security relevance}
Adversarial attack research is inherently dual use.
On one hand, such work helps reveal weaknesses in machine-learning systems and supports the development of stronger evaluation practice and more robust models.
On the other hand, the same techniques can be repurposed for malicious goals.
This concern is especially relevant for black-box attacks, because black-box capabilities are often closer to what an external adversary could realistically possess \cite{papernot2017practical}.

In this project, the work is framed explicitly as robustness analysis rather than operational misuse.
The experiments are limited to a standard benchmark dataset and a pretrained classifier rather than a safety-critical deployed system.
The report also emphasises transparent threat-model specification, explicit reporting of query cost, and careful discussion of limitations.
That framing matters professionally because it avoids presenting attack success as a sensational result detached from context.

\subsection{Responsible scope and communication}
A professional computing report must communicate both capability and limitation.
For that reason, the report is careful not to overstate what the experiments establish.
The findings concern one dataset, one main model family, a one-pixel black-box threat model, and a fixed set of explanation methods.
They are not presented as universal truths about all classifiers or all interpretability methods.

This is especially important when discussing explanation change.
A shift in a post-hoc explanation map does not by itself prove a causal theory of model reasoning.
The report therefore treats explanation metrics as diagnostic measurements of stability and faithfulness under perturbation, not as definitive windows into the internal semantics of the model.
That restraint is professionally important because the explainability literature is already prone to overclaiming.

\subsection{Data, privacy, and consent}
The experiments use CIFAR-10, a public benchmark dataset widely used in machine-learning research \cite{krizhevsky2009cifar}.
No personal user data is collected, no sensitive metadata is processed, and no human participants are involved.
Within the scope of the conducted experiments, privacy and consent risks are therefore minimal.

Even so, responsible data handling remains relevant.
Public benchmark use does not remove the obligation to document the data source clearly, describe scope honestly, and avoid implying claims the dataset cannot support.
This is especially relevant in adversarial ML, where visually compelling examples can create an exaggerated sense of real-world generality if the benchmark context is not stated clearly.

\subsection{Reproducibility and research integrity}
Research integrity is a central professional issue for experimental computing projects.
The implementation is therefore structured around fixed evaluation indices, recorded run configurations, frozen result artefacts, and a report pipeline that imports generated tables and figures rather than copying values manually.
This supports traceability from the final text back to concrete CSVs, summaries, and plots.

The report also clearly distinguishes between prior work and original contribution.
The one-pixel attack formulation, DE, Grad-CAM, Integrated Gradients, RISE, and CIFAR-10 are all externally sourced and explicitly cited \cite{su2019onepixel,storn1997de,selvaraju2017gradcam,sundararajan2017ig,petsiuk2018rise,krizhevsky2009cifar}.
The project's contribution lies in the specific comparative framing, the frozen artefact pipeline, and the integrated evaluation of sparse adversarial success, cost, and explanation behaviour.
Maintaining that distinction is both academically and professionally necessary.

\subsection{Compute cost and sustainability}
Large-scale adversarial evaluation can be computationally expensive.
The project therefore takes several steps to reduce unnecessary waste: fixed evaluation indices, reusable frozen artefacts, early stopping where appropriate, separation of attack generation from explanation generation, and a report pipeline that avoids repeated recomputation during writing.
These choices do not eliminate the environmental cost of compute, but they do reflect a professional obligation to plan experiments carefully and avoid avoidable reruns.

This issue is not merely logistical.
Responsible computing increasingly includes attention to computational resource use.
A professionally mature project should therefore consider not only whether an experiment is technically possible, but also whether it has been designed efficiently and reported in a way that preserves value from the compute already spent.

\subsection{Dependence on third-party software and licences}
The artefact depends on third-party open-source software, including Python, PyTorch, and supporting scientific libraries.
These are external dependencies rather than original contributions.
A professional submission must therefore document them clearly, respect their licences, and avoid presenting library functionality as if it had been authored within the project.

The same applies to reused research ideas and benchmark artefacts.
The report distinguishes between original code, imported libraries, benchmark datasets, and cited methods.
That distinction matters for attribution, reproducibility, and honest communication of what the project actually contributes.

\subsection{Professional summary}
The main professional issues in this project are therefore not incidental add-ons.
They are part of the substance of the work.
Adversarial research is dual use, explainability is easy to overclaim, and large-scale empirical computing must be reproducible and responsibly scoped.
A professionally strong project in this area must therefore combine technical competence with careful framing, transparent evidence, and restraint in interpretation.
